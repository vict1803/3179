# Diabetes in Australia — An unequal picture

A complete, buildless FIT3179 Data Visualisation 2 project: **12 charts, including 3 distinct map idioms**, on one scrolling webpage. Charts are authored in Vega-Lite or Vega, with readable individual JSON files.

## Open the project

1. Unzip this folder.
2. For a quick **static preview**, open `index.html`. Charts display from their generated SVG previews; filters are disabled in this mode.
3. For the **interactive version**, open a terminal in this folder and run:

   ```bash
   python3 serve.py
   ```

4. Open **http://localhost:8000**. Stop with Ctrl+C.

Alternative: open the folder in VS Code and use Live Server on `index.html`.

No npm installation, API key, login, or external CDN is needed. Vendor JavaScript is included locally. Internet is needed only when opening external source links.

## Editing fonts and the AI declaration

See `docs/EDITING_GUIDE.md`. The top of `style.css` controls the heading/body fonts and spacing. In `index.html`, search for `ai-declaration-text` to edit the visible AI declaration.

## Interactions

- **Trend measure:** switch between registered-person counts and age-adjusted prevalence; no misleading dual axis.
- **Sex:** filter the historical trend, age/sex heatmap and disadvantage comparison together.
- **State:** select a state or click its mark to highlight all three maps. Reset restores the overview.
- **Risk profile:** select a legend item to focus on one profile.
- Hover for published estimates and uncertainty. Dashboard download links and numerical tables are removed; source files remain in the repository.

## Publish on GitHub Pages

Upload the **contents** of this folder to the root of your own public GitHub repository. Keep the relative folder structure intact. Enable GitHub Pages for the branch and root containing `index.html`. See [GitHub's official Pages instructions](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

Then open the public Pages URL and confirm all charts load. The individual JSON files and source data remain accessible in the same repository. No public repository or deployment was created as part of this folder delivery.

## Required work before submission

- **Draw your own A4 sketch by hand.** The brief gives zero for a digitally created sketch. Use the guide, incorporate your actual tutor feedback, then scan/photograph it and export it to PDF in `sketch/`. Do not present generated code or a digital wireframe as a hand-drawn sketch.
- Ensure the finished page adheres to your submitted sketch. If your earlier sketch differs, resolve this with your tutor.
- Publish to **your own GitHub account**, add the final page and sketch URLs to the Moodle template, and review the draft submission description.
- Retain the AI acknowledgement, amend it truthfully if you change the work, and understand every chart for the interview.

## Rebuild (optional)

Opening the webpage does not require Python packages or Node. To reproduce the processed data, Python needs `openpyxl`; Node is needed only for the chart validation script.

```bash
python3 scripts/prepare_data.py
python3 scripts/prepare_boundaries.py
python3 scripts/build_specs.py
python3 scripts/build_cartogram.py
node scripts/validate_charts.cjs validation
```

The boundary script downloads the original ABS shapefile if no temporary cached copy exists. After rebuilding, copy the 12 default SVGs from `validation/` into `previews/` to refresh the static preview. Avoid uploading the temporary validation directory to GitHub.
